# BookWise AI — Document Intelligence & Verification Engine

> **Tagline:** *"Find answers in your documents. Verify every source."*  
> **Repository:** [https://github.com/Molly-Arora02/Bookwise-AI](https://github.com/Molly-Arora02/Bookwise-AI)

BookWise AI is an evidence-grounded document intelligence platform built to eliminate hallucinations in document question answering. Operating on publisher catalogues, academic collections, and institutional documents, BookWise AI guarantees that every factual answer is directly supported by physical source evidence, accompanied by exact page-level citations, and explicitly abstains with `Not found` whenever evidence is absent or subjective.

The initial commercial release indexes the complete 91-page **Orient BlackSwan History Catalogue 2024–25** (`History_2024-25.pdf`).

## 3. How BookWise AI Was Built (Step-by-Step)

BookWise AI was engineered using a modular, decoupled architecture:

```
Source PDF (History_2024-25.pdf)
    ↓ [1. PyMuPDF Page-by-Page Extraction & Normalization]
DocumentPages (91 pages, dual PDF & printed page coordinates, SHA-256)
    ↓ [2. LangChain Semantic Text Splitter]
TextChunks (895 cohesive chunks, 800 char window, 150 char overlap)
    ↓ [3. Local ONNX all-MiniLM-L6-v2 Embeddings]
Persistent ChromaDB Vector Store (Cosine similarity space + Index Manifest)
    ↓ [4. Hybrid Candidate Retrieval + Neighbor Expansion]
Top-K Candidates (Semantic vector score + Exact lexical boost + Adjacent chunks)
    ↓ [5. Evidence Support Validation Stage]
Grounding Decision
    ├── If Validated Evidence Found → Grounded Answer + Physical Citation
    └── If Insufficient / Subjective / Off-Topic → Exact 'Not found'
```

### Step 1: High-Performance Document Extraction (`src/bookwise/pdf_loader.py`)
- Extracted all **91 pages** of the Adobe InDesign PDF using **PyMuPDF** (`pymupdf`).
- Preserved physical PDF page indices (1 to 91) alongside catalogue printed page numbers:
  - PDF Page 1: Front Cover
  - PDF Page 2: Front Matter Publisher Info (corresponds to printed page 1)
  - PDF Page 3: Table of Contents
  - PDF Pages 4 to 90: Catalogue body & indices (`printed_page = pdf_page - 3`)
- Cleaned whitespace while harmonizing Indian DTP Rupee formatting (converting ASCII backtick `` ` `` to `₹` so searches for both succeed).
- Computed SHA-256 cryptographic checksums for both the whole file (`1af230e1c7...`) and individual page contents.

### Step 2: Semantic Chunking & Provenance Tracking (`src/bookwise/chunking.py`)
- Used LangChain's `RecursiveCharacterTextSplitter` with `chunk_size=800` characters and `chunk_overlap=150` characters.
- Produced **895 cohesive semantic chunks**.
- Attached rich provenance metadata to every chunk: `chunk_id`, `pdf_page`, `printed_page`, `global_chunk_index`, `source`, and `content_hash`.

### Step 3: Persistent Vector Storage with Change Detection (`src/bookwise/vector_store.py`)
- Stored embeddings in a persistent **ChromaDB** collection with cosine similarity indexing.
- Used the local **ONNX `all-MiniLM-L6-v2`** model (runs completely offline with zero external API dependencies or fees).
- Implemented duplicate-ingestion prevention: checks the disk manifest (`index_manifest.json`) against the file checksum and skips redundant re-indexing in **1.47 seconds**.

### Step 4: Hybrid Candidate Retrieval & Neighbor Context Expansion (`src/bookwise/retrieval.py`)
- Retrieves candidate chunks using vector similarity.
- Applies a hybrid lexical boost for dates, numbers, prices, and entity mentions.
- Expands boundary context by retrieving adjacent neighbor chunks (`global_chunk_index - 1` and `global_chunk_index + 1`) to ensure sentences spanning chunk boundaries are never truncated.

### Step 5: Evidence Validation & Strict Abstention (`src/bookwise/answer_engine.py`)
- Validates query structure (rejects empty inputs or oversized queries).
- Filters subjective queries ("best", "opinion", "recommend") and off-topic queries before retrieval.
- Verifies that candidate chunks contain the specific factual claim requested.
- Guarantees exact string equality for ungrounded queries: `Not found`.

### Step 6: Citation Verification (`src/bookwise/citations.py`)
- Cross-references cited page numbers against document bounds (1 to 91).
- Confirms that the cited evidence snippet physically exists on the claimed page text.
- Formats dual coordinates: e.g., `PDF Page 2 (Catalogue Page 1 (Front Matter))`.

### Step 7: Strict Light Warm UI Design System (`app.py` & `.streamlit/config.toml`)
- Fully compliant with the non-negotiable color guidelines: **zero black or blue backgrounds**.
- Uses an elegant palette:
  - Main background: Warm ivory (`#faf8f5`)
  - Sidebar background: Soft cream (`#f5f0e6`)
  - Content cards: White (`#ffffff`) with warm sand borders (`#e8e1d7`)
  - Buttons: Terracotta (`#c86446`) with hover states
  - Badges: Sage green (`#eaf0e8`) and terracotta (`#faece8`)
  - Typography: Warm dark charcoal (`#2b2826`) and warm taupe (`#5a534c`)

## 5. Installation and Setup Instructions

### Prerequisites
- macOS, Linux, or Windows
- Python 3.11 or later

### 1. Clone the Repository
```bash
git clone https://github.com/Molly-Arora02/Bookwise-AI.git
cd Bookwise-AI
```

### 2. Set Up Virtual Environment
```bash
python3 -m venv .venv
source .venv/bin/activate   # On Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

### 3. Document Ingestion
Place `History_2024-25.pdf` in the `data/` folder and run:
```bash
python ingest.py
```
*(Ingestion indexes all 91 pages and 895 chunks into persistent ChromaDB storage in ~26 seconds. Subsequent runs detect unchanged checksums and verify in 1.4 seconds).*

### 4. Run Automated Tests
```bash
pytest -v
```
All 22 unit, integration, and acceptance tests will execute and pass.

### 5. Launch the Web Application
```bash
streamlit run app.py
```
Open **[http://localhost:8501](http://localhost:8501)** in your browser.
